# ADR-0003: Minimal trusted UI Document

- Status: Proposed
- Linear: ENG-22
- Depends on: ADR-0001 and ADR-0002

## Context

React must render data independently of the domain ontology. The first architecture draft listed many components: tables, trees, graphs, timelines, images, and others.

Implementing all of them before the zero-epoch vertical slice would make the UI contract large without proving that the generated views need those components. A smaller trusted core can already display every base fact and the Prolog artifacts central to the research.

## Decision

UI Document v0 contains a minimal closed component vocabulary.

### Structural components

```text
Page
Section
```

### Data components

```text
Property
TextBlock
RawProlog
Diagnostic
```

### Property value kinds

```text
TextValue
ResourceLinkValue
```

`Property` contains an array of values, so a separate `PropertyList` component is unnecessary.

`Section` replaces both `Group` and top-level layout containers in v0.

## 1. Root contract

```json
{
  "schemaVersion": "0.1",
  "epoch": 0,
  "revision": 17,
  "page": {
    "kind": "page",
    "id": "entity:person_1",
    "title": "Иван",
    "sections": []
  },
  "diagnostics": []
}
```

A UI Document is immutable for its `(EpochId, Revision)` pair.

## 2. Generic entity fallback

Every entity is renderable without a type-specific profile.

The generic resolver:

1. selects the preferred label using the language policy;
2. obtains outgoing and incoming base facts;
3. groups facts by `(direction, predicate)`;
4. resolves a predicate label or falls back to a compact resource identifier;
5. maps literals to `TextValue`;
6. maps IRIs to `ResourceLinkValue`;
7. places technical predicates in a collapsed technical section rather than dropping them;
8. optionally adds a `RawProlog` section for research inspection.

No base fact may disappear merely because its type or predicate is unknown.

## 3. Property component

```json
{
  "kind": "property",
  "id": "property:out:fog:name",
  "predicate": "fog:name",
  "label": "Имя",
  "direction": "outgoing",
  "values": []
}
```

Directions:

```text
outgoing
incoming
derived
```

Values are grouped by predicate. Sorting and grouping are view rules, not React behavior.

## 4. Value source

Each data value declares whether it is a base or derived result.

Base source:

```json
{
  "kind": "base",
  "factId": "f:sha256:...",
  "origins": ["o_archive_1"]
}
```

Derived source:

```json
{
  "kind": "derived",
  "ruleId": "rule:sbras_academician",
  "evidenceFactIds": ["f:sha256:1", "f:sha256:2"]
}
```

A value is editable only when its source is `base` and the server sets `editable: true`.

React does not turn a derived result into Add/Delete operations.

## 5. Text value

```json
{
  "kind": "text",
  "text": "Иван",
  "language": "ru",
  "datatype": null,
  "editable": true,
  "source": {
    "kind": "base",
    "factId": "f:sha256:...",
    "origins": ["o_archive_1"]
  }
}
```

The lexical representation is displayed without silently changing it. A datatype may influence the editor later, but v0 may still use a text input.

## 6. Resource link value

```json
{
  "kind": "resourceLink",
  "targetId": "organization:isi",
  "label": "ИСИ СО РАН",
  "editable": true,
  "source": {
    "kind": "base",
    "factId": "f:sha256:...",
    "origins": ["o_archive_1"]
  }
}
```

When no label exists, `label` is the compact target identifier. The link remains usable.

## 7. TextBlock

`TextBlock` is plain text generated by a stable rule or Search result. Markdown and arbitrary HTML are excluded from the trusted v0 renderer.

```json
{
  "kind": "textBlock",
  "id": "summary:1",
  "text": "Найдено три связанных проекта."
}
```

When it states data-derived information, it should carry a derived source.

## 8. RawProlog

```json
{
  "kind": "rawProlog",
  "id": "search:query",
  "title": "Запрос Prolog",
  "code": "answer_person(Person) :- ...",
  "artifactKind": "query"
}
```

Artifact kinds:

```text
query
data
view
rule
diagnostic
```

Raw Prolog is rendered as text, never evaluated in the browser.

## 9. Diagnostic

```json
{
  "kind": "diagnostic",
  "id": "limit:1",
  "severity": "warning",
  "message": "Результат ограничен 200 узлами."
}
```

Severities:

```text
info
warning
error
```

Truncation, unsupported generated components, and fallback behavior must be visible through diagnostics.

## 10. Technical section policy

Technical and normally hidden facts remain accessible in a section with:

```json
{
  "kind": "section",
  "presentation": "technical"
}
```

React renders it collapsed by default. This preserves the invariant that fallback rendering loses no base facts.

## 11. Validation before React

The server rejects a UI Document when any of the following is true:

1. unsupported `schemaVersion`;
2. unknown component or value kind;
3. missing or duplicate component ID;
4. component nesting exceeds configured depth;
5. component, value, or byte limits are exceeded;
6. a base `factId` does not exist at the declared revision;
7. a displayed base value does not correspond to that fact;
8. `editable: true` is set for a derived value;
9. derived evidence references missing base facts;
10. a resource link target is structurally invalid;
11. RawProlog exceeds limits or is not plain text;
12. the document contains HTML, script, executable URLs, or arbitrary React properties.

A rejected generated document falls back to the generic entity page.

## 12. Prolog representation

SWI-Prolog may construct the same contract as dictionaries:

```prolog
View = _{
    schemaVersion: "0.1",
    epoch: Epoch,
    revision: Revision,
    page: _{
        kind: page,
        id: PageId,
        title: Title,
        sections: Sections
    },
    diagnostics: Diagnostics
}.
```

The JSON schema, not ad-hoc predicate arity, is the external UI contract.

## 13. Deferred components

The following are not part of trusted UI Document v0:

```text
Table
Tree
Graph
Timeline
Image
Map
Form
Tabs
arbitrary HTML/CSS/JS
```

They may enter a later UI contract version after a Builder/Search experiment demonstrates:

- a repeated need;
- a stable data contract;
- safe rendering;
- a useful fallback when unavailable.

Search may generate HTML/CSS in an isolated experimental branch, but that output is not equivalent to a validated UI Document.

## 14. Verification cases

1. Unknown entity type with known predicates.
2. Unknown predicates with literals and IRIs.
3. Several values for one predicate.
4. Russian label available.
5. No Russian label, English fallback available.
6. No labels, compact identifier fallback.
7. Incoming relation.
8. Technical fact remains available in collapsed section.
9. Base value exposes FactId and editability.
10. Derived value exposes rule and evidence and is read-only.
11. Raw query, data, and view Prolog fragments render as text.
12. Invalid generated component causes generic fallback.
13. Every active base fact is represented exactly once in either normal or technical sections.

## Rejected alternatives

### Large component ontology in epoch 0

Rejected because it expands React and validation before the research has shown which rich representations are useful.

### Arbitrary component props from Prolog or LLM

Rejected because it turns the UI contract into an unbounded remote code/configuration surface.

### Trusted Markdown or HTML text blocks

Rejected for v0. Plain text is sufficient for summaries and avoids a second rendering/security language.

### Hiding unknown or technical facts completely

Rejected because it violates inspectability and can conceal information from both users and architecture tests.

## Consequences

- The zero-epoch renderer is small enough for a vertical slice.
- Every graph fact remains visible without type-specific React code.
- Builder and Search initially focus on composition and logic rather than visual novelty.
- Rich visualizations remain possible through explicit future contract versions and the separate experimental HTML path.
