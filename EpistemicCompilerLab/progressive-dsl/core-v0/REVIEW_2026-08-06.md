## Positive findings

1. The new code is isolated under `EpistemicCompilerLab/` and explicitly marked experimental.
2. `unknown`, explicit opposition and conflict are not intentionally collapsed.
3. Numeric interval comparisons preserve abstention when a threshold crosses the interval.
4. D2 keeps conflict separate from uncertainty and distinguishes dependent averaging from independent cumulative combination.

These positives justify retaining the work as a synthetic semantic-kernel prototype after correction. They do not justify calling it a source-grounded course test or a consolidated Epistemic DSL runtime.

## Blocking findings

### P0 — The claimed CTO-course test does not use the course repository

`management-course-cases-v0.jsonl` is a local six-row synthetic fixture. It contains no:

- source repository;
- source commit;
- source path;
- source content hash;
- package hash;
- provenance record.

Only `rb.cto.technology_strategy.support` is found in the real course world. The IDs `course.risk.material.support`, `incident-review-*` and `load-test` are not present in `Sergey303/CTO-Practical-Simulation` at the reviewed commit.

The course repository already owns the real data and already compiles `worlds/management` through a pinned LogicLens runtime. Therefore the current six-case test may be called a synthetic management smoke test, but it is not a test on course data.

**Required resolution:** move course-owned fixtures and source bindings to `CTO-Practical-Simulation`, or make that repository the consumer contract that invokes the reviewed LogicLens core at a pinned commit. LogicLens should keep only domain-neutral synthetic fixtures.

### P0 — The core bypasses the trusted package and provenance boundary

For DSL-A and DSL-B, support is established by receiving any non-empty evidence ID string. The runtime does not verify that the assertion exists, matches a declared predicate/target, carries provenance, belongs to a valid dependency group or comes from a verified package.

For DSL-C, the request directly supplies numeric values rather than loading a typed observation from a verified package.

Consequently the core can pass while `worlds/management`, generated assertions, source provenance or capsule compilation are missing or broken. This contradicts the project source-of-truth and trusted-evaluator rules.

**Required resolution:** the core must dispatch to or wrap the existing package runtimes (`capsule_query.py`, `capsule_query_dsl_b.py`, `capsule_query_dsl_c.py`, D2 runtime) instead of accepting pre-asserted evidence as truth. If it remains a pure kernel, rename it to `semantic-kernel-smoke` and remove claims that it consolidates the executable DSL boundary.

## Major findings

### P1 — A/B/C semantic drift is not checked

`verify_contract.py` compares the new implementation only with `opinion-d2/runtime.py`. DSL-A, DSL-B and DSL-C are not compared with their existing reference/package runtimes.

The output contracts already differ. Examples include changed action names, loss of package/query/predicate/provenance fields, a non-DAG logical proof and absence of generated-assertion verification.

**Required resolution:** add matched golden comparisons against the existing A/B/C runtimes using one verified package, or eliminate duplicate A/B/C implementations and use adapters.

### P1 — The D2 check is Python-to-Python, not an independent oracle

The new GitHub workflow installs only Python and `jsonschema`. `verify_contract.py` calls D2 `compute()` but never invokes its SWI-Prolog verification path. Two similar Python implementations can share the same bug.

**Required resolution:** install SWI-Prolog and invoke the independent D2 verification kernel, or consume a previously verified immutable D2 frame with a pinned hash.

### P1 — JSON Schema and runtime disagree for rational values

The rational pattern accepts invalid strings such as `1/2.3`, while `fractions.Fraction` rejects them. The integer branch also accepts negative integers while the runtime rejects negative evidence. Base rates are not constrained to `[0,1]`.

**Required resolution:** use separate exact schemas for non-negative evidence, positive prior weight and unit-interval base rate. Add schema/runtime agreement tests for malformed rationals, negative values, zero denominators and base rates outside `[0,1]`.

### P1 — The fixture is called frozen but is not hash-frozen

The test pins case IDs and selected outcomes, but not the fixture bytes, external source commit, source files or generated package. Cases and expected values can be changed together without breaking the test.

**Required resolution:** add a manifest with fixture SHA-256, source repository/commit/path hashes, runtime commit, schema hash and expected-frame hash.

### P1 — Identity and provenance invariants are incomplete

The schema/runtime do not reject duplicate `premiseId` or duplicate `reportId`. The core D2 report schema omits required provenance. Strict/logical/numeric cases contain no source addressability at all.

**Required resolution:** enforce unique semantic identities and carry provenance/dependency metadata through every result frame.

## Test gaps

- incompatible units;

- incompatible base rates;

## Acceptance conditions for the revision

The revision may return for technical review when all of the following hold:

1. course-owned tests run from `CTO-Practical-Simulation` against a pinned LogicLens commit;
2. real `worlds/management` data is compiled and verified before queries;
3. every external source input has repository, commit, path and hash provenance;
4. A/B/C use existing verified runtimes or have exact compatibility tests;
5. D2 invokes an independent SWI-Prolog check;
6. rational schema and runtime accept exactly the same domain;
7. fixture and expected frames are hash-frozen;
8. duplicate IDs and missing provenance fail closed;
9. adversarial cases listed above are green;
10. a completed CI run or retained workflow artifact is linked.

## Final decision

**REVISE.** Keep the implementation only as an experimental synthetic semantic-kernel prototype until the trusted package boundary and cross-repository course contract are restored.
